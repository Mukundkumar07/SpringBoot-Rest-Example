================================================================================
                  PROFESSIONAL COMMIT ANATOMY
================================================================================

Professional commits have this structure:

┌─ Type (required)
│  ┌─ Scope (optional but good)
│  │         ┌─ Brief summary (50 chars max)
│  │         │
   feat(database): Add book search functionality
   
   Longer description here explaining what was done
   and why it was done.
   
   This description can be multiple lines and should
   answer: WHAT, WHY, and HOW

Breakdown:
──────────

Type:        feat (could be: feat, fix, docs, refactor, perf, test, chore)
Scope:       database (the part of code affected)
Subject:     Add book search functionality (what was done)

Body:        Multiple paragraphs explaining:
             - What was changed
             - Why it was changed
             - Implementation details
             - Testing done
             - Benefits

Footer:      Optional - references to issues, breaking changes, etc
